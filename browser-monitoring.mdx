`@onepatch/rum` sends page views, clicks, `fetch` and XHR spans, JS errors and web vitals to your workspace, each under a session id and joined to the backend trace it caused.

Paste this into your coding agent, with the endpoint and token from **Workspace settings → integrations**:

```text
Add OnePatch browser monitoring to this frontend.

First, install the setup skill (one-time):
npx skills add 1patch/skills -s rum-instrument

Then instrument the browser with the URL and write-only token.
Endpoint: https://your-org.logger.onepatch.dev. Token: op_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.
```

It finds your entry point, wires identity, checks your backends' CORS, and records what it did in `TELEMETRY.md`. This is the same write-only token your services use, so it is safe to commit, like a Sentry DSN.

Commit and push. Sessions arrive the next time someone loads your app:

```text
Which browser sessions has acme-web recorded in the last 15 minutes?
```

## If your API is on another origin

Same-origin calls are joined to their backend traces automatically. A cross-origin API needs two things: list it in `connectTracesTo`, and add `traceparent` to its `Access-Control-Allow-Headers`. If it takes cookies, name `traceparent` explicitly — a wildcard is invalid for credentialed requests.

Skipping it breaks nothing. Each listed origin is probed at startup and gets trace headers only if it accepts them; an origin that refuses is left alone and logs the fix, and you lose the join rather than the request. Your ingest endpoint needs nothing — it already answers browser preflights.

## By hand

```sh
bun add @onepatch/rum
```

```ts
import { identifyUser, startRum } from "@onepatch/rum";

await startRum({
  ingestUrl: "https://your-org.logger.onepatch.dev",
  ingestToken: "op_…",
  appName: "acme-web",       // becomes service.name; keep it stable, queries pivot on it
  environment: "production",
  appVersion: commitSha,     // required
  connectTracesTo: ["https://api.acme.com"], // cross-origin backends only
});

identifyUser({ id: user.id, email: user.email, orgId: user.orgId });
```

Call `startRum` once, early, on a client path, and `identifyUser` where your app knows who is signed in. Name your product's own steps with `recordAction("ran-workflow", { workflowId })`.

Every option is in the [package README](https://github.com/1patch/rum). The package is Apache-2.0 and speaks plain OTLP.

## Privacy

Spans record URLs, timings and error messages. The DOM is never captured, so keystrokes and form contents never leave the browser. Console capture is off by default.

URLs keep their query strings, because that is usually where the URL says *which* thing — `?workflow=42`. Set `scrubQueryStrings: true` if yours carry reset tokens or email addresses rather than ids.
