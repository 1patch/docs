`@onepatch/rum` captures page views, clicks, `fetch` and XHR spans, JS errors and web vitals. Each one carries a session id and, where your backend accepts trace headers, the same trace id as the server span.

There is no session replay: no DOM, no keystrokes, no form contents.

## Before you start

Take your ingest URL and token from **Workspace settings → Integrations** — the same pair your backend uses. The token is write-only and scoped to your tenant, so it belongs in your bundle the way a Sentry DSN does.

## Install with a coding agent

Paste this into your agent, with your own URL and token:

```text
Add OnePatch browser monitoring to this frontend.

First, install the setup skill (one-time):
npx skills add 1patch/skills -s rum-instrument

Then instrument the browser with the URL and write-only token.
Endpoint: https://your-org.logger.onepatch.dev. Token: op_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.
```

It finds your entry point and auth path, wires identity, checks your backends' CORS, and records what it did in `TELEMETRY.md`.

## Install by hand

```sh
bun add @onepatch/rum   # or npm / pnpm / yarn
```

```ts
import { identifyUser, startRum } from "@onepatch/rum";

await startRum({
  ingestUrl: "https://your-org.logger.onepatch.dev",
  ingestToken: "op_…",
  appName: "acme-web",
  environment: "production",
  appVersion: commitSha,
  connectTracesTo: ["https://api.acme.com"], // only if your API is cross-origin
});

identifyUser({ id: user.id, email: user.email, orgId: user.orgId });
```

| Option | |
| --- | --- |
| `ingestUrl` | Your tenant's ingest URL, with or without the trailing `/v1/traces`. |
| `ingestToken` | Your `op_…` token. |
| `appName` | Becomes `service.name`. Name it `<service>-web` after the backend it talks to, and keep it stable — every query pivots on it. |
| `environment` | Becomes `deployment.environment.name`. Read it where your backend reads its own. |
| `appVersion` | Required. Becomes `service.version`; pass the commit sha your build already exposes. |
| `connectTracesTo` | Cross-origin backends to join traces with, as explicit origins. Same-origin requests are joined automatically. |

Call `startRum` once, early, on a client path. Call `identifyUser` wherever your app already knows who is signed in; sessions before that point are recorded anonymously. Every option is in the [package README](https://github.com/1patch/rum).

Name your own steps with `recordAction("ran-workflow", { workflowId })`. Clicks and navigations are already captured; three to six named steps on the paths that matter beats wrapping every button.

Trace headers make a cross-origin request preflighted, and a backend whose `Access-Control-Allow-Headers` omits `traceparent` refuses it outright. So each origin in `connectTracesTo` is probed at startup, propagation is enabled only where the header is accepted, and an origin that refuses is left alone and logs the fix. `await startRum` resolves with which origins connected. The cost of a strict backend is a missing correlation, never a broken request.

## Verify

Browser spans land beside your backend spans, so ask in the same chat:

```text
Which browser sessions has acme-web recorded in the last 15 minutes?
```

## Privacy

No DOM, no replay, no keystrokes, no form contents. Console capture is off by default.

URLs keep their query strings and fragments, because that is usually where the URL says *which* thing — `?workflow=42`, or a hash route. Set `scrubQueryStrings: true` if yours carry reset tokens or email addresses rather than ids.

The package is Apache-2.0 and speaks plain OTLP.
