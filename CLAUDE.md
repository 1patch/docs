# OnePatch docs

Mintlify. Merging to `main` deploys to docs.onepatch.dev.

## Changelog rules

One `<Update>` per week, 1–3 items. An item is one sentence, two if it earns it.

1. Lead with the change, not the fact that something changed. "Home is a review queue," not "We've improved the home page."
2. Name what the reader sees and where they see it. If you can't point at it, it isn't an entry.
3. Numbers beat adjectives. "Five minutes to under two," not "much faster."
4. No announcement voice. Never "we're excited," "introducing," "say hello to."
5. No selling words: seamless, powerful, robust, intuitive, effortless, delightful.
6. No hedges: "helps you," "allows you to," "designed to." Say what it does.
7. No three-beat cadence ("faster, simpler, and more reliable") and no "not just X, but Y."
8. Don't pad to three items. One real change beats three filler ones.
9. Link to the guide instead of explaining it twice.
10. Removals and breakage get an entry in the same plain voice as features.
11. Never write about the changelog itself — how it's made, how complete it is, what's coming to it. Customers came for the product.

Read it aloud. If it sounds like a press release, rewrite it.
