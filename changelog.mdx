---
title: Changelog
description: What's new in OnePatch.
---

<Update label="On-call paging" description="Sep 17, 2026" tags={["Incidents"]}>
  The agent investigates incidents and pages the on-call responder when it needs a human decision or action, explaining what's needed and linking to the relevant fix or evidence. Your team's rules determine what warrants an interruption, and pages follow your on-call rotation through Slack DMs or SMS. See [Set up paging](/paging).
</Update>

<Update label="Skills library" description="Sep 17, 2026" tags={["Agent"]}>
  The agent can follow your team's procedures across conversations. Save a procedure as a skill and run it from chat with a slash command.
</Update>

<Update label="Evidence behind the diagnosis" description="Sep 9, 2026" tags={["Incidents"]}>
  The agent shows why it reached a diagnosis and whether a fix is working, with production charts and traces alongside its findings.
</Update>

<Update label="Agent instructions" description="Sep 7, 2026" tags={["Agent"]}>
  Admins can set workspace-wide instructions under Settings → Agent — your team's conventions, production context, and rules for taking action.
</Update>

<Update label="Services" description="Sep 5, 2026" tags={["App"]}>
  The Services page brings together the agent's map of your system: each service's health, monitors, dashboards, and dependencies. See what calls what, including the external services your system relies on.
</Update>

<Update label="React Native and Expo support" description="Sep 5, 2026" tags={["Telemetry"]}>
  Collect product analytics, crash logs, and other telemetry from native apps built with React Native and Expo. The agent investigates mobile issues alongside your backend telemetry.
</Update>

<Update label="Set up OnePatch from the terminal" description="Sep 4, 2026" tags={["API"]}>
  OnePatch sets up your workspace and connects the repository you're working in, including the coding agents on your machine. Start with `onepatch onboard` from your terminal.
</Update>

<Update label="Coding-agent plugins" description="Sep 1, 2026" tags={["API"]}>
  Claude Code, Codex, and Cursor can query your telemetry, read incident investigations, and hand work to the OnePatch agent from inside the editor. `npm install -g onepatch && onepatch install` sets up every agent on the machine. See [Coding agents](/connect-your-agent).
</Update>

<Update label="Linear integration" description="Aug 28, 2026" tags={["Agent"]}>
  Connect Linear from the Integrations page and the agent reads your issues for
  context while it investigates, and can create and update them in your workspace.
  It works under its own Linear identity, so everything it writes is attributed
  to OnePatch.
</Update>

<Update label="Workspace search" description="Aug 25, 2026" tags={["App"]}>
  ⌘K finds anything in the workspace — chats, incidents, monitors, and dashboards. The agent searches the same index, so a new incident starts with a look through past ones.
</Update>

<Update label="Agent internet access" description="Aug 20, 2026" tags={["Agent"]}>
  The agent can use the internet while it investigates, scoped to a domain allowlist you control. See [Network allowlist](/network-allowlist).
</Update>

<Update label="Verify PRs in prod" description="Aug 16, 2026" tags={["Monitors"]}>
  After a pull request merges, the agent watches the change in production and reports on the PR whether it held up. A review comment before merge says what it will watch, and a regression opens an incident. See [Verify PRs in prod](/verify-prs-in-prod).
</Update>

<Update label="Watched Slack channels" description="Aug 12, 2026" tags={["Slack"]}>
  Point the agent at a Slack channel and it reads every new message there, opening a thread on the ones that need attention. Turn it on from the integrations screen or with `@onepatch watch` in the channel. See [Watched channels](/incidents-and-slack#watched-channels).
</Update>

<Update label="Browser monitoring" description="Aug 12, 2026" tags={["Telemetry"]}>
  When something breaks for a user, the agent can see what that user actually did — the pages, clicks, failed requests, and JS errors of their session, each joined to the backend trace it caused. Setup is adding `@onepatch/rum` to the frontend. See [Browser monitoring](/browser-monitoring).
</Update>

<Update label="Episodes" description="Aug 10, 2026" tags={["Incidents"]}>
  When a new incident turns out to be part of one already open, the agent merges them into a single episode. You follow one thread instead of a row of separate chats.
</Update>

<Update label="AWS account access" description="Aug 7, 2026" tags={["Agent"]}>
  Connect an IAM role from the Integrations page and the agent can describe resources, read logs, and take whatever actions the role's policies allow while it investigates. Permissions stay on your side, and every action lands in your CloudTrail named for the chat that made it. See [AWS](/connect-aws).
</Update>

<Update label="Agent memory" description="Aug 6, 2026" tags={["Agent"]}>
  One workspace-wide memory that carries across chats, so the agent doesn't start cold every time.
</Update>

<Update label="Email-inbox monitors" description="Aug 4, 2026" tags={["Monitors"]}>
  Every workspace gets an ingest address. Forward alert email from any vendor and it becomes telemetry a monitor can act on.
</Update>

<Update label="API keys" description="Aug 2, 2026" tags={["API"]}>
  Mint machine credentials for the MCP endpoint from the app, and rotate them without downtime.
</Update>

<Update label="Keyboard and screen-reader support" description="Jul 15, 2026" tags={["App"]}>
  Chat, dashboards, monitors, the command palette, and onboarding are navigable by keyboard and announced to screen readers.
</Update>

<Update label="Production dashboards" description="Jul 15, 2026" tags={["Dashboards"]}>
  Dashboards show how your services behaved during an incident, with filters and a shared time window across charts. Individual charts have links you can share with your team.
</Update>

<Update label="Live Slack incident cards" description="Jul 2, 2026" tags={["Slack"]}>
  The Slack card rewrites itself as the incident moves through its phases, so the channel shows current state rather than a pile of updates.
</Update>

<Update label="Incident status card" description="Jul 1, 2026" tags={["Incidents"]}>
  Incident chats open with a status-page-style card — what fired, what phase it's in, what changed — pinned beside the transcript.
</Update>

<Update label="Bring your own MCP servers" description="Jun 30, 2026" tags={["API"]}>
  Connect any OAuth-protected MCP server from the Integrations screen and the agent can use its tools. See [How OnePatch works](/how-onepatch-works#the-agent-over-your-data).
</Update>

<Update label="Talk to the agent from Slack" description="Jun 22, 2026" tags={["Slack"]}>
  DM the OnePatch bot, or @-mention it in a channel and it replies in a thread. Each conversation is a real chat that also shows up in the app, with the sender's name. See [Incidents and Slack](/incidents-and-slack).
</Update>

<Update label="Longer query windows" description="Jun 16, 2026" tags={["Telemetry"]}>
  Queries run over much longer windows and return faster. Your signals live in a ClickHouse database scoped to your workspace.
</Update>

<Update label="Isolated workspace networks" description="Jun 12, 2026" tags={["Platform"]}>
  Every workspace runs in its own private network with signed images and no credentials shared between workspaces.
</Update>

<Update label="The agent opens pull requests" description="Jun 1, 2026" tags={["Agent"]}>
  Fixes arrive as a PR against your connected repo rather than a suggestion in chat.
</Update>

<Update label="Group chats" description="Jun 1, 2026" tags={["Chat"]}>
  Org-wide chats where every message carries its author, so the agent knows who is speaking.
</Update>

<Update label="The agent asks questions" description="May 28, 2026" tags={["Agent"]}>
  When the agent needs a decision mid-task, the choices render in the composer and your answer goes straight back into the run.
</Update>

<Update label="Chat while the agent works" description="May 13, 2026" tags={["Chat"]}>
  Send a message mid-response and the agent picks it up instead of making you wait for the turn to end.
</Update>

<Update label="Images in chat" description="May 13, 2026" tags={["Chat"]}>
  Drag or paste a screenshot into the composer.
</Update>

<Update label="Per-workspace telemetry ingest" description="May 12, 2026" tags={["Telemetry"]}>
  You get an OTLP endpoint and a token. Anything you send becomes queryable by the agent.
</Update>
