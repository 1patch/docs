title: Changelog

---

<Update label="Change verification" description="Aug 16, 2026" tags={["Monitors"]}>
  Every pull request on a connected repo gets a plan while the code is still in review: one review comment listing what the agent will watch once the change ships, and what would fail it. A temporary monitor checks those signals from deploy through a three-day soak, then reports the verdict — verified, regression, or inconclusive — on the same comment. A regression opens an incident. See [Change verification](/change-verification).
</Update>

<Update label="Watched Slack channels" description="Aug 12, 2026" tags={["Slack"]}>
  Point the agent at a Slack channel and it reads every new message there without an @-mention, opening a thread on the ones that need attention. Turn it on from the integrations screen or with `@onepatch watch` in the channel. See [Watched channels](/incidents-and-slack#watched-channels).
</Update>

<Update label="Pull requests on the home page" description="Aug 11, 2026" tags={["App"]}>
  The home page leads with the pull requests the agent has opened, each with the monitor history that prompted it — enough to judge the change without leaving the page. Underneath, a table lists every pull request across your connected repos.
</Update>

<Update label="Phone and tablet layout" description="Aug 10, 2026" tags={["App"]}>
  The app lays out for small screens instead of assuming a desktop window.
</Update>

<Update label="Episodes" description="Aug 10, 2026" tags={["Incidents"]}>
  When a new incident turns out to be part of one already open, the agent merges them into a single episode. You follow one thread instead of a row of separate chats.
</Update>

<Update label="AWS account access" description="Aug 7, 2026" tags={["Agent"]}>
  Connect an IAM role from the Integrations page and the agent can describe resources, read logs, and take whatever actions the role's policies allow while it investigates. Permissions stay on your side, and every action lands in your CloudTrail named for the chat that made it. See [AWS](/connect-aws).
</Update>

<Update label="Agent memory" description="Aug 6, 2026" tags={["Agent"]}>
  One workspace-wide memory that carries across chats, so the agent doesn't start cold every time.
</Update>

<Update label="Email-inbox monitors" description="Aug 4, 2026" tags={["Monitors"]}>
  Every workspace gets an ingest address. Forward alert email from any vendor and it becomes telemetry a monitor can act on.
</Update>

<Update label="API keys" description="Aug 2, 2026" tags={["API"]}>
  Mint machine credentials for the MCP endpoint from the app, and rotate them without downtime.
</Update>

<Update label="Monitor recovery is a signal" description="Jul 27, 2026" tags={["Monitors"]}>
  A check going green re-opens the question instead of closing the incident on its own.
</Update>

<Update label="Histogram view" description="Jul 25, 2026" tags={["Telemetry"]}>
  OTLP histograms are exposed as a typed view the agent can query directly.
</Update>

<Update label="Keyboard and screen-reader support" description="Jul 15, 2026" tags={["App"]}>
  Chat, dashboards, monitors, the command palette, and onboarding are navigable by keyboard and announced to screen readers.
</Update>

<Update label="Chart share links" description="Jul 15, 2026" tags={["Dashboards"]}>
  Any single chart on a dashboard has its own URL.
</Update>

<Update label="Incident dispatch that doesn't give up" description="Jul 15, 2026" tags={["Incidents"]}>
  Hand-off retries every tick until an agent acknowledges it, and resolution waits until the check is observed green. A dead-man alarm fires if monitor evaluation itself stops.
</Update>

<Update label="Live Slack incident cards" description="Jul 2, 2026" tags={["Slack"]}>
  The Slack card rewrites itself as the incident moves through its phases, so the channel shows current state rather than a pile of updates.
</Update>

<Update label="Incident status card" description="Jul 1, 2026" tags={["Incidents"]}>
  Incident chats open with a status-page-style card — what fired, what phase it's in, what changed — pinned beside the transcript.
</Update>

<Update label="Bring your own MCP servers" description="Jun 30, 2026" tags={["API"]}>
  Connect any OAuth-protected MCP server from the Integrations screen and the agent can use its tools. See [MCP](/connect-your-agent).
</Update>

<Update label="Workspace switcher" description="Jun 30, 2026" tags={["App"]}>
  A full-page switcher lists every org you belong to.
</Update>

<Update label="Monitors list with sparklines" description="Jun 27, 2026" tags={["Monitors"]}>
  Rows collapse to a status sparkline and open into a two-pane detail view.
</Update>

<Update label="Talk to the agent from Slack" description="Jun 22, 2026" tags={["Slack"]}>
  DM the OnePatch bot, or @-mention it in a channel and it replies in a thread. Each conversation is a real chat that also shows up in the app, with the sender's name. See [Incidents and Slack](/incidents-and-slack).
</Update>

<Update label="Dashboard filters" description="Jun 22, 2026" tags={["Dashboards"]}>
  The agent can define dropdowns and multi-selects that sit under the time tape and filter the whole board.
</Update>

<Update label="Dashboard tabs from files" description="Jun 17, 2026" tags={["Dashboards"]}>
  Every root `.tsx` file in your workspace becomes a dashboard tab named after the file.
</Update>

<Update label="Longer query windows" description="Jun 16, 2026" tags={["Telemetry"]}>
  Queries run over much longer windows and return faster. Your signals live in a ClickHouse database scoped to your workspace.
</Update>

<Update label="Isolated workspace networks" description="Jun 12, 2026" tags={["Platform"]}>
  Every workspace runs in its own private network with signed images and no credentials shared between workspaces.
</Update>

<Update label="Documentation" description="Jun 10, 2026" tags={["Docs"]}>
  Public docs at [docs.onepatch.dev](https://docs.onepatch.dev), with a [getting-started guide](/getting-started) and reference for monitors, dashboards, and incidents. Written to be read by an agent as well as a person — the full text is at [llms-full.txt](https://docs.onepatch.dev/llms-full.txt).
</Update>

<Update label="Incidents" description="Jun 2, 2026" tags={["Incidents"]}>
  A monitor that fires opens a chat named after it, and the agent works the incident from there through a real state machine. A check that can't run at all pages the agent too.
</Update>

<Update label="Full-page dashboards" description="Jun 1, 2026" tags={["Dashboards"]}>
  A saved dashboard opens at full width on its own page. Axes and tooltips carry units, and dragging to zoom applies the new range to every chart on the board.
</Update>

<Update label="The agent opens pull requests" description="Jun 1, 2026" tags={["Agent"]}>
  Fixes arrive as a PR against your connected repo rather than a suggestion in chat.
</Update>

<Update label="Group chats" description="Jun 1, 2026" tags={["Chat"]}>
  Org-wide chats where every message carries its author, so the agent knows who is speaking.
</Update>

<Update label="The agent asks questions" description="May 28, 2026" tags={["Agent"]}>
  When the agent needs a decision mid-task, the choices render in the composer and your answer goes straight back into the run.
</Update>

<Update label="Command palette" description="May 28, 2026" tags={["App"]}>
  ⌘K jumps to any chat, dashboard, or monitor.
</Update>

<Update label="Monitors" description="May 23, 2026" tags={["Monitors"]}>
  A monitor is a TypeScript program on a cron that queries your telemetry and returns a result. The agent writes and edits them; they live in a folder tree in your workspace repo.
</Update>

<Update label="Chat while the agent works" description="May 13, 2026" tags={["Chat"]}>
  Send a message mid-response and the agent picks it up instead of making you wait for the turn to end.
</Update>

<Update label="Images in chat" description="May 13, 2026" tags={["Chat"]}>
  Drag or paste a screenshot into the composer.
</Update>

<Update label="Per-workspace telemetry ingest" description="May 12, 2026" tags={["Telemetry"]}>
  You get an OTLP endpoint and a token. Anything you send becomes queryable by the agent.
</Update>

<Update label="First light" description="May 10, 2026" tags={["Platform"]}>
  Sign in, connect a GitHub repo, get a provisioned workspace with an agent in it.
</Update>
